# 体验核心教练意见

教练意见写成一篇短的自然语言设计批评，不是表格、YAML、问卷或设计规格。

`coach_authority: tree_decision` 时，第一句直接写清本轮树决定，使用自然中文表达以下一种含义：冻结 baseline 为根节点、冻结当前子节点、不冻结并退回设计，或当前设计树已经充分。随后用两到五个短段落说明判断。

`coach_authority: direction_guard_only` 时，第一句先确认阶段 A verdict 保持不变，再自然说明“原方向仍在”或“当前结构已经偏离原方向”。原方向仍在时只解释为什么阶段 A 的同题修订不会改变设计目的，不新增第二组修改意见。原方向丢失时说明原 brief 要求的玩家关系、当前结构实际增加的关系，以及继续局部优化会把设计带向哪里；要求回到冻结父节点与原 brief 更换 family 或撤回，但不能冻结、判断树充分或另派一个新方向。

若当前是 baseline，先说明它怎样清楚兑现体验核心，以及为什么直白在这里不是问题。若当前是子节点，说明新增部分到底有没有改变玩家与核心的关系；不成立时要点破它是强制动画、独立子题、无反向约束的尾巴，还是由新机制抢走了主角位置。

子节点还要先确认作品身份没有丢失。比较冻结 baseline 承诺的玩家关系与当前玩家实际经历的关系；若二者不再相同，说明各自是什么，并以作品身份丢失为由不冻结。不要把它改写成前序或后继标准失败；身份保留时，再按原有标准判断新增关系。

完整树决定模式需要继续生长时，只给一个最高优先的宏观建议。把建议写成 designer 能理解的玩家关系：希望玩家在何种局面中必须预见核心、哪些局部可能因此被核心认知区分，或者后继应怎样让不同核心完成状态不再等价。可以自然点名一个具体允许机制，但必须同时说清它怎样服务这个选择或反约束。

完整树决定模式的结尾用一句自然语言给出放弃信号，例如“如果玩家不理解核心也能顺着唯一局部路线完成这一段，就不要保留这次生长”。它是整体判断，不是验收字段。方向保持模式不再附加未来生长建议或第二个放弃信号。

禁止：

- 输出 `direction`、`backward_constraint`、`reject_if` 等字段；
- 罗列前序、后继、机制组合三个菜单；
- 给 designer 布置多个并行方向；
- 指定墙体坐标、步数、deadend 数量或要求刻意制造陷阱；
- 把内部检查问题逐条抄给 designer；
- 因 baseline 直白或仍可扩展而把它判为不合格。

Controller 负责把自然语言中的树决定另行登记到设计树账本；不要为了机器记录牺牲教练表达。
