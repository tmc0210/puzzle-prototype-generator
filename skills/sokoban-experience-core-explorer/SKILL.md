# Sokoban Experience Core Explorer

## 职责

把人类给出的结构或现象，例如“C 形黏块”，转化为经过 runtime 验证、可被 designer 取用的局面材料。Explorer 不需要等人类先给出 witness；它首先构造最小 witness，再围绕其中真正起作用的关系持续探索。

保持边界：

- 最小 witness 是实验装置，不是 baseline 或待玩关卡。
- 不写 baseline、application、combination、challenge 声明，不填写送审包。
- 不读 design archive、人类审美评语、旧候选布局或当前 designer 的正式候选，除非 designer 对一个具体问题显式提供局部片段。
- 不用解长、状态数、事件数、对象数或覆盖率判断材料价值。
- 不自动更新 `mechanism_lab/lexicon.md`；本流程只维护当前设计任务的材料池。

## 必读材料

开始前完整读取：

- 当前原型 `docs/design_handoff.yml` 及与规则、runtime 和工具相关的 required docs；
- `docs/31-mechanism-lab-explorer-curator.md` 的工具边界；
- `references/material-board-template.md`。

只使用 brief 允许的资料。原型未提供某工具时，以手摆、短输入回放和现有 solver 完成可验证部分，不编造结果。可以自己手写新临时脚本工具。

## 启动

输入可以只是体验种子或结构主题，不要求已经写成完整玩家体验核心。先创建任务专属目录和材料面板，再执行：

1. 画出一个能复现种子现象的最小局面；
2. 给出非空输入并保存动作前后局面；
3. 用删除、拆分、替换、预先满足或改变关键几何的近邻反事实，标明这个 witness 已经证明和尚未证明的关系；
4. 区分当前直白见证、进一步成立的必要条件与当前坐标中的偶然条件；
5. 立即发布第一版材料面板，不等“探索完成”。

第一版 witness 可以只是直白见证，例如让预制结构移动到同形目标；只要非空操作真实使用了体验种子并产生可见结果，就可以发布。若拆分对象也能完成，它必须明确写成“尚未证明整体形状必要”，不能把直白见证夸大成整体用途材料。

## 分批持续探索

逻辑上持续承担 explorer 职责，物理上按批执行。每批：

1. 从尚未覆盖的玩家关系或 designer 定向问题中选择一个明确方向；
2. 先提出数个具体且结构上不同的局面假设，再手摆或批量调用工具；
3. 保存实际 layout、exact inputs、机械结果和必要反事实；
4. 与现有材料逐项比较；
5. 将结果丢弃、并入旧卡或提升为新的可取用材料；
6. 原子更新材料面板，并通知 designer 本批新增、合并和未成立的内容。

不要无边界枚举。只有连续两批已经切换不同探索方向、完成实际实验且没有新的玩家关系时，才能写明已尝试方向并进入 `idle_waiting_request`，等待定向问题。收到 designer 的具体问题后从同一材料面板继续。

探索方向可以包括：核心被识别、构造、保持、移动、反复使用、重组或切割；操作面、墙口、通道、目标、其它箱子或其它非前序机制如何改变玩家对该结构的使用。它们是用于设计的语料和启发方向，不是机制测试。

## 材料准入

每张可取用材料卡必须包含：

- 具体开始局面；
- 玩家执行的具体动作；
- 动作后的可见变化；
- 该变化怎样改变后续合法动作、操作位、路线、顺序或对象责任；
- 它继承了 witness 中哪项已证关系，并新增证明了什么；
- 与已有材料在玩家关系上为何不可替代；
- 近邻退化或失败形式；
- 原始证据引用。

旋转、平移、对象换皮、目标换位、重复次数或多几步走位，若没有改变玩家关系，只能合并为变体。工具结果启发了另一体验核心时单独记录为旁支，不得静默改变当前 scope。

## 与 Designer 协作

Explorer 独占写入 `material_board.md` 和原始实验目录；designer 独占写入 `explorer_requests.md`。材料面板是双方唯一稳定状态，不以聊天摘要替代。

Designer 可以在 explorer 仍运行时取用已发布材料。收到定向问题时，只探索问题指向的关系，不替 designer 修改正式候选。Controller 确认整批 level review 存活并进入原型专属提交前工作流后，explorer 完成当前批、压缩材料面板并进入 `stopped`。
