# Candle Sokoban 课程规划：执行计划与长期校准

状态：前四个机制阶段已收口；正在探索第五阶段“退焰点火”。

## 目标

- 为 Candle Sokoban 规划一条约 20—25 关的 game jam 主线。
- 关卡槽位必须由可玩的体验核心支撑，不能由 runtime 事件、规则条目或机制覆盖数直接生成。
- 不考虑 jam 生产成本；篇幅只用于主线与备选的优先级取舍，不降低体验核心标准。
- 第 1 关建立轴推、烛芯和点盆；第 2 或第 3 关必须让玩家看到倒计时跨界与蜡烛缩短，尽早兑现倒计时主题。

## 永久判断标准

一个结构只有同时回答以下问题，才可能占据关卡槽位：

1. 玩家在机制发生前做了什么有意义的选择？
2. 选择留下了哪段长度、哪格空位、哪个阻挡、火焰状态或操作位差异？
3. 哪个最小后继动作实际消费了这个差异？
4. 用错对象、方向、顺序或时机后，后续行动或可解性怎样实质改变？
5. 它是否只是普通阻挡、普通走位、事件 witness 或已有结构的重复？
6. 它与相邻核心是否存在不可合并的玩家推理差异？

碰火死亡、无效输入不走表、烛身不会被火点燃等负事实不单独占关。语句形式是否为否定不是标准；若某个状态能被主动保存并由后继消费，例如未燃重曝，它仍可成为结构的一部分。

## 阶段顺序

1. 基础操控：轴推、烛芯点盆、侧滚。
2. 倒计时与燃烧：长滚的一行动时间价值、缩短、燃尽、多烛同步燃烧。
3. 墙体灭火：从某次共享燃烧边界退出、保长、拆分参与集合。
4. 共享火焰与复燃：延迟加入、退出后重新加入、控制停烧区间。
5. 烛身遮蔽与未燃重曝：用可移动蜡烛同时改变明灭状态与空间关系。
6. 退焰点火：缩短释放格与同边界火焰转移。
7. 滚动途中接触链：滚动小步结算、接触顺序写入状态、后续小步或边界读取状态。
8. 全机制组合：不新增规则，只组合前面已选出的强结构。

机制暴露仍服从 `docs/mechanic_exposure_sequence.yml`。后阶段 Explorer 可以假定已冻结的前序掌握，但不得提前使用更晚家族。

## 每阶段循环

1. Controller 用玩家能力描述本阶段的新机制，不用事件名代替设计目标。
2. Controller 先提出 2—4 个具体探索主题。每个主题必须写成“开始摆法 → 关键选择 → 动后具体局面 → 最小 consumer”。
3. 顺序派遣 fresh Explorer，明确调用 `$sokoban-mechanism-lab`，使用 `mechanism_explore/task_local`。每个 batch 只处理一个设计空间，先列 3—6 个近邻变体，再用 runtime 核对。
4. Explorer 记录局面卡片、结构谱、正反例、最小用法、误用边界与原始证据。只有事件 witness 的结果留在 run，不进入正向 lexicon。
5. Controller 回收并从玩家侧判断作品潜力，不让 Explorer 决定关卡数量、难度或课程优先级。
6. 每阶段默认先跑两个 batch；必要时追加一个明显不同的救援主题。没有强结构时允许该机制不单独占关，不能强行填槽。
7. 阶段收口后冻结实际玩家先验，再推进下一组机制。

## 产物分层

本任务严格区分三类成果：

1. `Lexicon` 只记录可独立拼接的细粒度局部结构。它必须有最小 consumer，但不承载完整玩家命题；规则事实、事件 witness 和完整动作链都不属于 Lexicon。
2. `experience_core` 记录课程真正评估的体验核心：玩家选择、动后差异、consumer 链、错误反事实与课程作用。权威账本是 `reports/curriculum_planning_20260725/experience_cores.yml`。
3. `optional_direction` 是 Explorer 为证明核心可用而做出的具体“伪关卡”或组合实例。它保留在 batch 的 `proposed_families.md`、cases、results 与 notes 中，可作为后续单关设计基石，但不约束最终布局。

Controller 回收时先把具体 witness 拆成 Lexicon 原子，再抽象体验核心。依赖唯一尺寸或唯一布局、无法更换 consumer 的结果不能直接占课程槽位；具体 witness 很漂亮也不等于发现了同等规模的新 Lexicon 家族。

## 结果分级

- `mainline_core`：优先进入主线的一至两个洞见或结构。
- `jam_reserve`：同样达到体验核心标准，但因与主线相似、课程位置较弱或 20—25 关篇幅限制而暂缓。
- `material_only`：有用的输入、consumer、结构旋钮或组合零件，但不足以独占一关。
- `reject`：规则复述、事件 witness、普通阻挡、无 consumer 或与已有结构重复。

`jam_reserve` 不降低质量标准，也不以生产成本为理由降级。

## 课程组装

- 不预先给每个机制分配固定关数；先探索并选核心，再组装约 20—25 关。
- 难度只使用全课程内部的 1—5 相对量表；5 是唯一最高档，不存在 5+ 或 6—8。机制更晚、组合更多不自动获得更高数字。
- 新机制首次出现时允许难度回落；随后用独立洞见深化，而不是重复同一动作。
- 阶段终盘组合本阶段最强结构，不追求事件全覆盖。
- 若强核心不足 20 个，继续探索真正不同的组合空间；不得用弱展示关凑数。
- 若强核心超过 25 个，把课程作用较弱但仍合格的结构放入 `jam_reserve`。
- 全部课程骨架确定后，才逐关通过 `$sokoban-level-design-studio` 进入完整单关设计与待玩交付。
