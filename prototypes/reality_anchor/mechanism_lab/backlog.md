# Reality Anchor 机制探索 Backlog

本文件只记录当前值得探索的新摆法或组合关系，给 mechanism loop 选题时作为 seed 之一。它不是历史 refresh，也不记录普通维护事项。已关闭 gap 的 provenance 保留在 `lexicon.md` 的证据段和 `runs/` 中，默认不再放在 backlog 入口。

## ra_gap_split_tail_second_consumer

- 状态：open
- 来源：`固定 B/S 切割`
- 想探索的摆法：第一段把黏块切开后，已经推进目标的左格或端点不再参与；旁边剩下的 sticky 或左侧 crate 柱继续进入第二段墙口、通道或目标。
- 开始摆法：`C+M`、`C+MM`、`CC+M`、`MMM`，或 C 形跨过 B/S 后形成但尚未证明有后续职责的 crate 柱与 sticky 组件。
- 想验证的动后局面：左格或端点进入第一个目标后，剩余 sticky 挡住返回格、进入窄通道，或 crate 柱继续推向另一处目标。
- 最小用法：单格目标袋之后紧接窄通道、返回站位或第二个墙口。
- 建议对照：剩余对象确实挡路的正例、空间过宽的绕过、整体刚体路线与分离组件路线是否等价、不同剩余长度。
- 不要重复：不要把 `sticky_to_box` 或 `sticky_split` 事件本身写成成果。
- 收口规则：只有形成稳定且不能被整体刚体路线等价完成的两段玩法时，才写入新条目或 recipe；否则关闭 gap。

## ra_gap_boundary_brush_goal_fill

- 状态：open
- 来源：`B/S 移动边界：箱组变为 CC、C+M 或黏块`
- 想探索的摆法：移动 B/S 边界，把远处箱组改成不同形状，再把它们送进同一个目标口。
- 开始摆法：可移动 B/S anchor，以及远处 `CC`、`C+M`、`C+MM`、2x2、双柱等箱组。
- 想验证的动后局面：不同箱组都可能覆盖目标，但门外分别留下零格、一格或多格 sticky，或者整块被低墙挡住。
- 最小用法：目标数量、目标口宽、门外通道宽度和低墙位置必须能区分这些箱组。
- 建议对照：目标少一格、通道宽一格、低墙错位；push / pull 只作为带动边界的对照。
- 不要重复：不要把 push 和 pull 拆成两个顶层条目，除非其中一种额外打开或关闭站位。
- 收口规则：若仍只是同一墙口的形状对照，补入原条目；若目标覆盖和门外剩余物形成新的顺序关系，再补 lexicon 或 recipe。

## ra_gap_pl_ratchet_drives_brush

- 状态：open
- 来源：`P/L 锚点在横廊中的可动性`、`B/S 移动边界：箱组变为 CC、C+M 或黏块`
- 想探索的摆法：P/L 锚点在横廊中只能移动固定次数，并把 B/S anchor 带到恰好能改出正确箱组的位置。
- 开始摆法：L 端前方留 1 或 2 格，B/S anchor 与 P/L 相邻，远处箱组位于边界会扫过的行列。
- 想验证的动后局面：P/L 只能停在某一格时，B/S 边界正好把远处箱组改成能过门的形状；多走或少走一格都会得到错误形状。
- 最小用法：`P/L 横廊定停位 -> B/S 边界停到指定行 -> 改写后的箱组过门`。
- 建议对照：P/L 多一格行程、少一格行程、B/S 刷线偏一格、侧廊开放。
- 不要重复：不要只证明 P/L 在横廊中单向；不要把长度差异都拆成新条目。
- 收口规则：若横廊只负责定停位，写 recipe 或原条目补充；若横廊还打开新的玩家站位，再考虑新结构族。

## ra_gap_pl_handle_brush_shortcuts

- 状态：open
- 来源：`P/L 横向把手`、`B/S 移动边界：箱组变为 CC、C+M 或黏块`
- 想探索的摆法：P/L 周围不同墙格是否真正决定 B/S anchor 能否移动到指定行，或是否留下侧路绕过。
- 开始摆法：P 侧 push、L 侧 pull、玩家前格墙、锚点半格目标墙、首步后的返回格，以及 B/S 边界停位。
- 想验证的动后局面：同一远处箱组下，不同墙位分别挡住玩家、挡住锚点或封住返回路线，从而让 B/S 边界停在不同位置。
- 最小用法：P/L 必须是移动 B/S anchor 的唯一方式，边界改写后还要接同一个墙口。
- 建议对照：玩家前格墙、锚点目标格墙、返回格墙、B/S 刷线偏一格。
- 不要重复：不要只报告 `destination_blocked` / `force_blocked`，必须说明最终箱组和过门结果怎样变化。
- 收口规则：若只是给已有墙位补证据，补入原条目；若 push / pull 造成不同站位或返回路线，再补结构谱。

## ra_gap_pull_sweep_sticky_blocker

- 状态：open
- 来源：`P/L pull 抽取`
- 想探索的摆法：垂直二格对象被拉动时，把侧边目标格上的 crate 换成 sticky，比较它会一起移动、与原黏块合并，还是完全挡住拉动。
- 开始摆法：玩家在 pull 侧，身后为垂直 B/S 或其他二格对象；侧边目标格依次放空地、墙、crate、单格 sticky 或二格 sticky。
- 想验证的动后局面：crate 被一起推走；sticky 可能合并成更大连体块，也可能因目标格无处可去而关闭整次动作。
- 最小用法：保持玩家前格相同，只更换侧边格内容，并比较拉动后的形状和合法动作。
- 建议对照：空格、墙、crate、单格 sticky、二格 sticky。
- 不要重复：不要只测试玩家前格墙；不要只测单 crate。
- 收口规则：若只是补充 blocker 类型，写入原条目；若 sticky 合并后形成新的可画形状和后续墙口，再考虑新 gap。

## ra_gap_split_endpoints_double_distribution

- 状态：open
- 来源：`box_sticky_normalize` 产生的两个独立 sticky 组件与 crate 柱。
- 想探索的摆法：让两个独立 sticky 组件承担两个方向、顺序或站位要求不同的 downstream 责任。
- 开始摆法：C 形跨过 B/S 后留下两个独立 sticky 组件与 crate 柱；两个目标消费者必须要求组件分开调度。
- 想验证的动后局面：两个组件分别完成不可互换的责任，而且完整 C 的原子整体平移无法等价完成同一组责任。
- 最小用法：两个目标口使用不同进入方向或先后站位，迫使两个组件分别移动。
- 建议对照：完整 C 整体路线、预先分离组件、只留一个消费者、改变 crate 柱位置、放宽目标口。
- 不要重复：只观察 `sticky_split`、`sticky_to_box` 或两个端点可以分别移动，不足以证明玩家侧用途。
- 收口规则：只有证明分离后的双责任不能被完整 C 整体路线替代时，才新建 lexicon 条目；否则关闭 gap。
