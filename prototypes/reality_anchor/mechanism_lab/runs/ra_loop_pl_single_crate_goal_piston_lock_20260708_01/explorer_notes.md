# Explorer Notes: P/L 单箱目标活塞顺序锁

## 探索边界

本轮只研究单箱 P/L 活塞在目标位上的一个很小用途：单箱被推入目标后，如果后续结构迫使玩家用 L 侧 pull 回撤，那么目标覆盖会被撤销。因此这个目标天然适合作为“必须最后达成”的顺序锁。

第一性原理拆分：

- 输入接口：P/L 边界旁的单箱活塞，玩家从 P 侧推箱进入 L 侧目标位。
- 产物：一个临时目标覆盖状态；玩家站在 L 侧，若向左退出会拉箱离开目标。
- 最小 consumer：狭窄通道迫使回撤，回撤动作消费并撤销临时覆盖；开放侧路反例说明没有“必须回撤”就不构成锁。

## 关键观察

### 1. 推入目标作为最后动作成立

`corridor_goal_last_action` 中，`right` 把 crate 推到 goal 上，最终渲染为 `*`，`final.isWin=true`。这说明单箱活塞虽然通常只是退化往复，但当伸出位是目标时，伸出态本身可以被目标消费。

### 2. 被迫回撤会撤销目标覆盖

`corridor_goal_then_forced_retract` 使用同一狭窄通道，动作 `right,left`：

- `right` 后 `after.isWin=true`，crate 覆盖目标；
- `left` 触发 `pull_object:crate#1`，最终 `final.isWin=false`，目标回到 `G`。

这就是顺序锁的核心：如果该局部结构后面还有必须执行的回撤动作，提前完成目标会被撤销。

### 3. 侧向出口会破坏顺序锁

`open_side_exit_preserves_goal` 打开上下空间后，`right,down` 中第二手只是 `walk`，crate 仍留在目标上，`final.isWin=true`。因此锁并不来自“单箱上目标”本身，而来自“目标覆盖后唯一可用出口是回撤 pull”。

### 4. 目标必须落在第一手伸出位

`corridor_goal_offset_no_temp_cover` 把目标向前偏一格。`right` 只把 crate 推到目标前，`after.isWin=false`；之后 `left` 回撤也不涉及目标覆盖。目标位置是 consumer，而不是任意目标都能形成顺序锁。

## 结论范围

已支撑：

- 单箱 P/L 活塞可以在伸出位目标上形成临时覆盖。
- 若狭窄通道使 `left` 成为唯一退出动作，回撤会拉出 crate 并撤销目标。
- 打开侧路会让玩家保留目标覆盖离开，因此不构成顺序锁。
- 目标偏离伸出位时没有临时覆盖，也就没有顺序锁。

未支撑：

- 没有测试多目标完整关卡，只证明局部顺序锁材料。
- 没有证明全局不可回返；本结构是局部顺序约束，不是永久锁。
- 没有测试箱链或 sticky 本体的目标顺序锁；这些属于另一个结构空间。
