# 建议结构族：绑定债与解绑定债

来源：`ra_struct_binding_unbinding_01`，`cases.yml` / `results.json` / `report.md`。

证据标签：动作回放与最终动作表为 `runtime_observed`；回返搜索为 `bounded_return`；局部状态枚举为 `bounded_graph`，runner 在本轮预算内报告 `complete`。

## 结构族 1：binding_debt_sticky_topology

### 局部问题

designer 什么时候应该把多个 crate 压成一个 sticky 刚体？这个结构族把“独立资源”改写成“形状化工具/阻塞物”，核心差异来自 crate 的邻接图和地形余量。

### 结构旋钮

- crate 邻接图：沿施力轴相邻、晚加入成 L 形、隔一行/隔一格。
- 地形余量：开放房间、单行走廊、是否能绕到刚体另一侧。
- 入场节奏：一次把一排推入，或先做横条再接入第三个部件。
- 后续消费面：刚体前方是否有递送空间、侧面是否有把手、走廊是否只允许轴向处理。

### 变体谱

`bind_bar_open`：二连箱压成横条工具。

```text
#########
#...BS..#
#.......#
#...@MM.#
#.....G.#
#########
```

设计用途：把两个 crate 的独立性换成一个 2 格横条。开放房间中最终 `up/down/left/right` 都合法，适合做可递送工具或后续切割输入。

`bind_l_corner`：三箱压成 L 形占角件。

```text
#########
#...BS..#
#...@M..#
#....MM.#
#.....G.#
#########
```

设计用途：第三个部件晚接入后，横条变成占角 footprint；最终 `up` 被 `force_blocked`，适合制造封角、卡门、单侧把手变化。

`bind_gap_keeps_parts`：隔行压入保留两个部件。

```text
#########
#...BS..#
#....M..#
#.......#
#...@MG.#
#########
```

设计用途：两个部件都进入 sticky 侧，但不正交接触，所以仍是两个资源。它是“材质转换不等于绑定债”的误用边界。

`bind_bar_choke`：走廊内横条成为宽塞。

```text
#########
#...BS..#
#########
#...@MMG#
#########
```

设计用途：同一横条在单行走廊中只剩左右轴向处理；本小图内回到初始为 `no complete`。适合做宽塞、一次性递送、或局部不可逆感，但不应泛化到所有走廊。

### 共同解释

绑定债的设计价值不在 `box_to_sticky` 事件，而在 **资源拓扑的改写**：

- 相邻 crate 被合成一个刚体后，designer 得到形状化工具，同时失去分别摆放的自由。
- L 形比横条更容易制造角落把手限制。
- 隔行/隔格入场保留多个部件，可用于避免过早绑定。
- 地形余量决定同一刚体是工具、负债，还是宽塞。

### 建议 curator 收录

建议收录，条件是条目名称保持为“绑定债 / sticky topology debt”，不要降成“crate 会变 sticky”。收录时应保留 `bind_gap_keeps_parts` 和 `bind_bar_choke` 作为误用边界。

## 结构族 2：unbinding_debt_resource_release

### 局部问题

designer 什么时候应该把 sticky 刚体切回 crate 资源？这个结构族把“单个形状化工具”改写回“可分配部件”，核心差异来自切割线覆盖 footprint 的位置和次数。

### 结构旋钮

- 切割覆盖：只切头、连续切完、切 L 形颈部、整列跨界。
- footprint 朝向：横条、竖条、L 形。
- 移动方向：垂直穿过边界会释放资源；沿边界搬运会保留刚体债。
- 后续地形：开放房间主要展示资源形态；受限门口/走廊才会把释放形态转成强顺序压力。

### 变体谱

`unbind_head_slice_once`：横条切头释放一个 crate。

```text
##########
#...BS...#
#........#
#...CM@..#
#......G.#
##########
```

设计用途：从一个 2 格刚体中先释放一个 crate，同时保留一个 sticky 尾。适合“先拿一个资源，尾部仍作为债等待处理”。

`unbind_full_bar_twice`：横条二次切割完全拆箱。

```text
##########
#...BS...#
#........#
#..CC@...#
#......G.#
##########
```

设计用途：连续切割把刚体完全回收为两个 crate。适合作为绑定债的完成释放端点。

`unbind_l_neck`：L 形切颈释放竖向双 crate 加尾。

```text
##########
#...BS...#
#...C....#
#...CM@..#
#......G.#
##########
```

设计用途：切割线穿过 L 形颈部时，释放出竖向相邻的 crate 资源，同时留下一个 sticky 尾。适合做“释放出的资源形状本身成为下一步工具”的结构。

`unbind_vertical_full_release`：竖条整列一次释放。

```text
##########
#...BS...#
#...C....#
#...C@...#
#......G.#
##########
```

设计用途：整列一次跨界，不留下 sticky 尾，直接得到竖向双 crate。适合作为干净的资源回收结构。

`unbind_parallel_carry`：沿边界平移保留刚体债。

```text
##########
#...BS...#
#........#
#....@...#
#....M.G.#
#....M...#
#........#
##########
```

设计用途：沿边界搬运时保持 sticky 刚体身份，适合先调整工具位置，再在别处切割。它是解绑定债的保守边界。

### 共同解释

解绑定债的设计价值不在 `sticky_to_box` 事件，而在 **切割线如何把一个 footprint 投影成资源形态**：

- 切头得到 `crate + sticky tail`，适合部分释放。
- 连续切割得到全 crate，适合完整回收。
- L 形切颈释放出的 crate 排布不同于横条，后续消费方式也不同。
- 沿边界搬运不释放资源，可用于延迟解债。

### 建议 curator 收录

建议收录为“解绑定债 / resource release by boundary cut”。但该族的本轮开放房间变体最终动作表大多四向可用，因此不要把它写成强锁结构；应写成资源形态语料。若要进入更强设计用法，下一轮应增加受限地形或 P/L 把手对释放后资源的消费。
