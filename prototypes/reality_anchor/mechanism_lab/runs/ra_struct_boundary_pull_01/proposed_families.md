# 建议结构族：移动边界刷子与 pull 抽取把手

来源：`ra_struct_boundary_pull_01`，`cases.yml` / `results.json` / `report.md`。

证据标签：动作回放与最终动作表为 `runtime_observed`；回返搜索为 `bounded_return`；本轮所有 case 的局部图均在预算内 `complete`，可标 `graph_complete`。首步非法 case 只作为把手关闭边界，不写回返结论。

## 结构族 1：bs_moving_boundary_brush

### 局部问题

designer 什么时候可以把 B/S anchor 当作“移动边界刷子”？这组结构让边界线扫过远处对象：对象没有被直接推走，但资源拓扑被重写为 crate、sticky 尾、2x2 刚体或多个柱状工具。

### 结构旋钮

- 边界运动方向：垂直跨过对象行，或沿边界方向平移。
- 被扫对象 footprint：横条、竖条、L 形、两行对齐、两行隔列。
- 切割覆盖：整行覆盖、只覆盖上半格、只切 L 形颈部。
- 绑定覆盖：上刷时是否把 crate 行与 sticky 行正交连接；列间隙是否保留多个组件。

### 变体谱

`brush_down_bar_full_release`：边界下刷，横条整行释放。

```text
##########
#.......G#
#.@......#
#.B..CC..#
#.S......#
#........#
##########
```

设计用途：把远处 2 格 sticky 横条整行回收为两个 crate，适合作为“边界线远程回收资源”的基础材料。

`brush_down_vertical_partial`：边界下刷，竖条切头。

```text
##########
#.......G#
#.@......#
#.B..C...#
#.S..M...#
#........#
##########
```

设计用途：只释放上半格，留下 sticky 尾；适合制造部分释放债。

`brush_down_l_tail`：边界下刷，L 形留尾。

```text
##########
#.......G#
#.@......#
#.B..C...#
#.S..MM..#
#........#
##########
```

设计用途：释放一个 crate 头，同时保留横向 sticky 尾，给后续动作留下不同于竖条的工具形状。

`brush_parallel_preserve_bar`：沿边界方向平移，保留横条债。

```text
##########
#.......G#
#.@B.....#
#..S.MM..#
#........#
#........#
##########
```

设计用途：移动 anchor 位置但不切割远处横条，可作为“先调边界锚，延迟切割”的边界材料。

`brush_up_bind_square`：边界上刷，两行资源绑定成 2x2。

```text
##########
#.......G#
#.B......#
#.S..MM..#
#.@..MM..#
#........#
##########
```

设计用途：把上行 crate 纳入 sticky 侧并与下行 sticky 合并，形成一个 2x2 刚体工具。

`brush_up_gap_keeps_columns`：边界上刷，隔列保留两个柱状工具。

```text
##########
#.......G#
#.B......#
#.S..M.M.#
#.@..M.M.#
#........#
##########
```

设计用途：同样上刷两行，但列间隙保留两个独立柱状工具；适合需要两个工具而不是一个大块的局部语法。

### 共同解释

这组结构显示 B/S anchor 可以作为“边界刷子”：移动的是边界，远处对象不必移动。垂直跨线运动会切割或绑定对象 footprint；沿边界方向平移会保留资源拓扑。最终差异不是事件名，而是 designer 得到 `CC`、`C+M`、`C+MM`、`2x2 M` 或两个柱状 `M` 工具。

### 建议 curator 收录

建议收录。它与既有“B/S 解绑定债”相邻，但不重复：旧条目是移动对象跨固定边界；本条目是移动边界跨远处对象。

## 结构族 2：pl_pull_extraction_footprint

### 局部问题

designer 什么时候可以把 P/L pull 侧当作“抽取把手”？这组结构比较同一个离开动作在单格物体、轴向二格物体、垂直二格物体、侧向墙格、侧向可移动资源之间如何变成抽取、封门或扫带。

### 结构旋钮

- 玩家前格：开放或墙封。
- 身后对象 footprint：单格 crate、沿轴 B/S anchor、垂直 B/S anchor。
- 侧向目标位：开放、墙、可移动 crate。
- 抽取后的局部动作集合：能否继续向同方向抽、反向是否被前格对象堵住、侧箱是否被带走。

### 变体谱

`pull_crate_pocket_extract`：单 crate 抽取。

```text
#########
#PL....G#
#.......#
#.@C....#
#.......#
#########
```

设计用途：玩家离开对象，crate 填入玩家旧格；适合做最小抽取把手。

`pull_crate_front_wall`：前格墙封死抽取。

```text
#########
#PL....G#
#.......#
#.#@C...#
#.......#
#########
```

设计用途：身后有对象也不能抽；玩家前格墙关闭把手。它是玩家移动门。

`pull_bs_horizontal_axis`：二格锚点沿轴抽取。

```text
#########
#PL....G#
#.......#
#.@BS...#
#.......#
#########
```

设计用途：沿抽取轴排列的二格物体可通过一格前进空间整体抽出，适合做长把手或移动边界。

`pull_bs_vertical_side_open`：竖向锚点需要侧向余量。

```text
#########
#PL....G#
#.......#
#.@S....#
#..B....#
#.......#
#########
```

设计用途：垂直 footprint 抽取需要侧向半格同步平移；它不是单纯的一格前格问题。

`pull_bs_vertical_side_wall`：侧向目标墙封死竖向抽取。

```text
#########
#PL....G#
#.......#
#..@S...#
#..#B...#
#.......#
#########
```

设计用途：玩家前格开放，但对象 footprint 的侧向目标格被墙关掉；这是独立于前格门的对象目标门。

`pull_bs_vertical_side_sweep_crate`：竖向锚点扫带侧箱。

```text
#########
#PL....G#
#.......#
#.@S....#
#.CB....#
#.......#
#########
```

设计用途：把侧向墙换成可移动 crate 后，抽取动作同步带走侧箱，形成扫带结构。

### 共同解释

这组结构把 pull 抽取拆成三层门：玩家前格门、对象 footprint 目标门、侧向 blocker 的可移动性。单 crate 和轴向二格物体主要消耗玩家前格；垂直二格物体还需要侧向目标位；侧向目标位若放入可移动资源，则从“封门”变成“扫带”。

### 建议 curator 收录

建议收录。它补充既有 P/L 条目的空白：已有条目主要描述 P/L anchor 自身的墙格门；本条目描述 pull 侧如何抽取一般对象或 B/S anchor，并把侧向 footprint 变成可调结构旋钮。
