# 玩家体验核心与单关包装方法论

状态：当前通用关卡设计方法论。

本文定义 Sokoban-like 单关创作的设计本体，回答“这关为什么值得存在、玩家实际体验什么、包装怎样服务它”，以及证据暴露问题时怎样保留玩家关系完成结构修订。执行循环见 [关卡设计工作室执行标准](21-level-design-studio-standard.md)；规则、runtime 与工具事实以原型文档为准。

## 基本命题

关卡首先是一段由玩家亲自见证或完成的具体体验；地图、步骤、机制组合和唯一解约束都应服务这段体验。

关卡设计是一种以硬证据为前提的艺术创作，不是机械合格题的批量生产。可解、唯一、无旁路或机制必经，只说明当前 exact version 满足硬证据，不说明它有趣、完整或值得存在。每轮任务只设计一个候选；目标不是比较多个设计，而是把同一候选修订到合格并交给人类试玩。

```text
玩家体验核心
-> 作品身份
-> 完整单关包装
-> 地图与操作
-> 硬证据与独立审查
```

## 体验种子与局部设计语料

人类输入可以只是一个值得研究的结构、现象或关系，例如“C 形黏块”，无需预先写出完整体验核心或提供局部结构小图。这类输入称为体验种子。

Task-local Mechanism Lab 先把体验种子展开为一个或多个极小、可运行、能通过非空输入清楚复现局部关系的局面材料。直白材料首先是实验装置；它可以证明某段结构关系存在，却不是正式候选，也不规定完整关卡应该多简单或多复杂。

任务内设计语料必须说清具体开始局面、玩家动作、可见变化、由此改变的后续操作关系、近邻退化和证据引用。旋转、平移、换皮、重复次数和额外走位不会自动形成新材料；只有动作后局面、操作位、路线、顺序或对象责任发生实质变化时才应分开记录。

结构主题是待展开的设计空间。单个摆法没有形成新关系时，只作为已有正向材料的对照或原始实验保留；完整候选、难度、审美和 structure family 取舍由 Designer 负责。

## 玩家体验核心

玩家体验核心描述玩家最终应亲眼看到或主动完成、并使本关值得存在的事情。它必须写成玩家可感的局面、操作与变化，不能只写机制名、事件标签或抽象主题。

至少说清：

- 玩家此前相信或预期什么；
- 开局或关键阶段出现什么矛盾、形状或可能性；
- 玩家实际执行什么操作；
- 棋盘发生什么可见变化；
- 为什么这次变化值得独立成为一关。

体验核心可以是规则首次被完整见证、看似死局的结构被救活、整体形状获得意外用途、玩家主动制造并使用某种状态，或两条已知规则碰撞后产生新的解释。构造对象也可以是死角、操作面、材料状态、边界关系、顺序窗口、通路或时机。

## 默认玩家先验

除非当前原型明确把不完全信息或精确操作本身作为机制，否则默认玩家拥有全图视野、基本类推箱经验、当前关卡位置要求的全部前置知识，以及正常的人类几何直觉和操作能力。玩家能够迅速识别显然的操作方向、基本可达性、局部几何关系和短死路，也能够稳定完成走位、绕位与对准。

读图失误、规则遗忘、操作不准、执行唯一操作，不构成谜题内容。判断难度时，应把这些已被玩家先验剪除的负担视为已经解决；只有其后仍需玩家建立的非显然关系、计划或选择，才可能构成谜题难度。一个简单作品可以因核心清楚、包装准确而成立，不需要虚构玩家困难来证明它“有题”。

人类玩家通常更擅长整体读取棋盘、使用几何直觉、迁移前置关卡形成的技巧，以及从构图和不谐元素中推断作者意图；LLM 与求解工具更擅长机械枚举、保存大量状态和发现偶然路线。关卡应主动以人类玩家擅长的能力作为主要参与方式，机械试错只用于后台探索与验证。

## 作品身份

作品身份把体验核心转化为可证伪的创作承诺。它不评价作品好坏，而是规定哪些关系消失后，这已经不是同一关。

```yaml
experience_statement: 玩家具体见证或完成什么
player_action: 玩家必须亲自做什么
visible_payoff: 关键操作后哪里发生可见变化
core_boundary:
  central_objects: 体验核心本身包含哪些对象或机制
  supporting_objects: 哪些对象只承担包装或反馈
identity_conditions:
  - 必须保持的形状、关系、时序或对象责任
identity_counterfactuals:
  - 替换、删除或预先满足某个条件后，核心体验为什么不再成立
```

作品身份优先使用正面关系描述，而不是罗列与作品无关的禁令。所有 exact version 都必须重新核对身份；版本号连续不代表作品身份自动连续。

## 完整单关包装

包装是为了呈现、准备、揭示、兑现和收束体验核心而存在的全部结构，包括开局构图、短测试、走位、前置准备、错误反馈、高潮与结束方式。

良好包装通常做到：

- 开局让玩家看见值得思考的对象、矛盾或形状；
- 只用必要的准备动作建立核心条件；
- 让玩家主动进入、制造或使用关键关系；
- 在关键操作后提供集中、可见的反馈；
- 高潮后尽快结束，不追加清理劳动；
- 关卡规模、对象数量和流程长度与回报相称。

直白呈现可以形成合格作品，但不会自动免除无意义走位、被动动画、高潮后清理或对象失职。反过来，关卡也不应为了显得完整而机械追加段落。Designer 应从第一次正式设计起就把候选当作最终单关，按体验核心实际需要决定包装深度。

### 前序构造的非拼接标准

前序不是把玩家送到核心局面的强制动画，也不是完成后整体退休的独立子题。Reviewer 应从实际布局和解路线判断：一个尚未理解“本关最终要构造什么核心局面”的熟练玩家，能否只靠局部判断轻松走完前序。若可以，前序没有让玩家为体验核心作选择。

合格前序会出现若干局部看似可行的构造方式，而玩家一旦预见核心所需的具体形状、接触面、顺序、操作侧或对象职责，就能显著压缩这些选择。错误构造可以自然形成死路或在后段暴露为不可用，但 deadend 数量只可作为 Critic 按需读取的局部事实，不是 Designer 指标或审美结论。

### 后继应用的非拼接标准

合格后继必须消费体验核心留下的具体状态，并把约束向前传回：有些能够完成眼前核心动作的状态，不能完成整关；玩家因此需要重新理解此前究竟要构造哪一种核心局面。

可以用删除测试检查这种关系：若拿掉后继，某个关键构造选择会明显变得更显然、若干原本需要区分的核心完成状态会重新等价，那么后继确实参与了同一个谜题。若后继只在核心结束后另起任务，不改变玩家此前的推理，它就是追加子题。

前序构造和后继应用是检查单关因果完整性的关系，不是流程阶段，也不是必须同时出现的配额。简单而集中的候选可以不需要复杂前序或后继；复杂候选则必须证明各段共同服务同一体验核心。

## 唯一候选与 exact version

每轮任务只维持一个 `candidate_id`。Designer 在同一工作台中持续修改布局、回放和结构假设；同一 family 内重构或更换 family 都服务同一个体验核心和候选目标。

`exact version` 是 Designer 完成当前设计、自查并准备送审时发布的不可变快照，不是每次施工改动的编号。首次发布前可以没有 exact；退回设计后，账本保留上一份已发布 exact 作为修订依据，工作中的布局不取得版本身份。下一份完整快照发布时才形成新的 exact version。

修改已发布 exact 的 layout、start、goal、胜利条件、核心机制使用或玩家关系，会使它的旧证据失效。旧 exact 只保存送审与审查 provenance，最终只有一个完成全部门禁的 delivery version 进入人类试玩。

## 审美的非补偿性

审美判断先问是否存在明确、可感、同题可修的缺点，例如无意义赶路、未兑现对象、喧宾夺主的前置流程、高潮后的清理劳动、割裂子题、视觉不谐或作品身份弱化。

任何明确缺点都不能靠事件覆盖、逻辑完整、难度、对象数量或其它亮点补偿。同时，设计野心与完成质量应分开：保守选择可以形成无缺点的完整作品；激进尝试可能达到更高上限，也可能整体失败。LLM 不负责给存活版本作最终审美排名；人类试玩与作者判断拥有最终权威。

## 工具与结构材料

Solver、graph、replay、counterfactual 和 event probe 只验证硬事实：可解性、解族和旁路，操作与状态变化是否真实，核心对象是否参与，以及作品身份中的机械关系是否成立。

机械证据只有约束和否决作用，不提供正向审美价值。工具不能证明关卡好玩、优雅、惊喜或应该进入游戏。Task-local Explorer、Lexicon、Mechanism Lab、矿工和局部结构库也只提供材料；材料被 Designer 提取、变形、选入明确体验核心并完成包装后，才成为作品的一部分。

## 结构修订：从差异到结构责任

结构修订以玩家关系为单位。出现 bypass、证据不支持设计声明，或当前布局无法表达体验核心时，先同时重放预期解与反例，找出它们实际分离的关系：对象尺寸或职责、进入方向、操作顺序与时机、必须保留的可达空间，或核心动作之后形成的局面。把修订目标说成“预期关系可以继续成立，而旁路所依赖的关系不能成立”，再决定怎样改变布局。

墙、地形、对象位置和目标位置是最小的局部约束手段。如果当前画布无法同时容纳预期操作和所需限制，可以插入行列、平移局部区域或增加必要的可动空间。修订时保存对象关系、操作方向和因果责任，不保存绝对坐标。

随后从允许的设计语料、task-local Mechanism Lab、手画或工具探索中寻找能够利用该差异的结构。委派给 Explorer 的问题必须改写成与完整候选坐标和包装无关的局部设计空间；Designer 保留候选和 family 的设计责任，自行提取、改造和组合返回材料。

筛选结构嵌入后，先确认预期解仍有足够操作空间，并实际重放预期解和已知反例；再移除脚手架、收回冗余空间和无意义移动，恢复可读性、节奏与回报，并检查新旁路。

只要所需约束能够在不改变主要体验的前提下由当前 family 表达，就继续修订这个 family。只有可行表达都会让筛选器取代体验核心、破坏作品身份，或反例证明原结构假设本身不成立时，才更换 family。结构修订在同一工作台中连续进行；修订结果完成自查并再次发布时才形成新的 exact，旧 replay、证据和审查不为它背书。

## 防漂移检查

设计过程中持续确认：

1. 玩家最终见证或完成的事情是否仍与体验核心相同；
2. 作品身份条件是否仍在规范解和所有允许胜解中成立；
3. 每段内容是否改变玩家与核心的关系，还是只增加流程；
4. 前序或后继内容是否与核心形成玩家可感的因果关系，而不是独立子题串联；
5. 修唯一解是否把整体形状降解成局部材料、把主动使用降解成被动动画。

## 方法边界

本方法不要求 Explorer 穷尽设计空间，也不能替代作者对机制和完整游戏节奏的理解。持续材料探索只增加 Designer 可调用的结构词汇；它不要求生产多个候选。唯一候选是否最终进入游戏仍由人类试玩决定。
