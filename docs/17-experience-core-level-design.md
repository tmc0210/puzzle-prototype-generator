# 玩家体验核心与关卡包装方法论

状态：当前通用关卡设计方法论。

本文定义 Sokoban-like 关卡创作的设计本体，回答“这关为什么值得存在、玩家实际体验什么、包装怎样服务它”，以及证据或生长需要暴露问题时怎样保留玩家关系完成结构修订。执行循环见 [关卡设计工作室执行标准](21-level-design-studio-standard.md)；规则、runtime 与工具事实以原型文档为准。

## 基本命题

关卡首先是一段由玩家亲自见证或完成的具体体验；地图、步骤、机制组合和唯一解约束都应服务这段体验。

关卡设计是一种以硬证据为前提的艺术创作，不是机械合格题的批量生产。可解、唯一、无旁路或机制必经，只说明版本满足硬证据，可以称为一个关卡，不说明它有趣、完整或值得存在。同一体验核心可以先形成一个直白但成立的 baseline，再从这个冻结根节点继续生长；后续版本的价值来自它改变了玩家与同一核心的关系，而不是单纯把流程加长。

```text
玩家体验核心
-> 作品身份
-> 包装
-> 地图与操作
-> 硬证据验证
```

## 体验种子与局部设计语料

人类输入可以只是一个值得研究的结构、现象或关系，例如“C 形黏块”，无需预先写出完整体验核心或提供局部结构小图。这类输入称为体验种子。

Task-local Mechanism Lab 先把体验种子展开为一个或多个极小、可运行、能通过非空输入清楚复现局部关系的局面材料。预制 C 形结构移动到同形目标可以构成直白材料；它证明玩家可以见证这个结构的运动，却未必证明完整形状不可替代或存在更深用途。

直白局面材料首先是实验装置。Designer 可以提取其中的结构逻辑并把它整理成一个合法、清楚、回报完整的 baseline；baseline 允许直白，不必提前承担后续包装的全部难度。它仍须让玩家亲自完成体验核心，而不能只是播放无需理解的机制动画。

Task-local Mechanism Lab 再围绕这个结构空间生产任务内设计语料：具体开始局面、玩家动作、可见变化、由此改变的后续操作关系、近邻退化和证据引用。旋转、平移、换皮、重复次数和额外走位不会自动形成新材料；只有动作后局面、操作位、路线、顺序或对象责任发生实质变化时才应分开记录。

结构主题是待展开的设计空间。“L 形黏块在墙口附近的可动性”会产出数量和覆盖范围不同的局部语料。单个摆法没有形成新关系时，它只作为已有正向材料的对照或原始实验保留；完整候选、难度、审美和 family 前途由 Designer 负责。

## 玩家体验核心

玩家体验核心描述玩家最终应亲眼看到或主动完成、并使本关值得存在的事情。它必须写成玩家可感的局面、操作与变化，不能只写机制名、事件标签或抽象主题。

至少应说清：

- 玩家此前相信或预期什么；
- 开局或关键阶段出现什么矛盾、形状或可能性；
- 玩家实际执行什么操作；
- 棋盘发生什么可见变化；
- 为什么这次变化值得独立成为一关。

体验核心可以是规则首次被完整见证、看似死局的结构被救活、整体形状获得意外用途、玩家主动制造并使用某种状态，或两条已知规则碰撞后产生新的解释。

它不要求“组装机器”。构造也可以是构造死角、操作面、材料状态、边界关系、顺序窗口、通路或时机。

## 默认玩家先验

除非当前原型明确把不完全信息或精确操作本身作为机制，否则默认玩家拥有全图视野、基本类推箱经验、当前关卡位置要求的全部前置知识，以及正常的人类几何直觉和操作能力。玩家能够迅速识别显然的操作方向、基本可达性、局部几何关系和短死路，也能够稳定完成走位、绕位与对准。

读图失误、规则遗忘、操作不准、执行唯一操作，不构成谜题内容。判断难度时，应把这些已被玩家先验剪除的负担视为已经解决；只有其后仍需玩家建立的非显然关系、计划或选择，才可能构成谜题难度。一个简单作品可以因核心清楚、包装准确而成立，不需要虚构玩家困难来证明它“有题”。

人类玩家与 LLM 及其工具具有不同的能力结构。人类玩家通常更擅长整体读取棋盘、使用几何直觉、迁移前置关卡形成的技巧，以及从有意安排的构图和对象位置或不谐元素中推断设计意图，这些方面 LLM 不是普通玩家的能力下界；LLM 与求解工具更擅长机械枚举、保存大量状态和发现偶然可行路线。关卡设计应主动以人类玩家擅长的能力作为主要参与方式，让玩家通过读取结构、迁移知识和理解作者安排获得进展；机械试错主要用于后台探索与验证，不能被直接当作玩家难度或作品价值。

## 作品身份

作品身份把体验核心转化为可证伪的创作承诺。它不评价作品好坏，而是规定哪些关系消失后，这已经不是同一关。

```yaml
experience_statement: 玩家具体见证或完成什么
player_action: 玩家必须亲自做什么
visible_payoff: 关键操作后哪里发生可见变化
core_boundary:
  central_objects: 体验核心本身包含哪些对象或机制
  supporting_objects: 哪些对象只承担包装或反馈
identity_conditions:
  - 必须保持的形状、关系、时序或对象责任
identity_counterfactuals:
  - 替换、删除或预先满足某个条件后，核心体验为什么不再成立
```

作品身份优先使用正面关系描述。例如“完整 C 形在关键操作前保持连通，凹口提供操作位，上下臂在同一次刚体移动中作用于两条物体线”，而不是罗列与作品无关的禁令。

## 包装

包装是为了呈现、准备、揭示、兑现和收束体验核心而存在的全部结构，包括开局构图、短测试、走位、前置准备、错误反馈、高潮与结束方式。

良好包装通常做到：

- 开局让玩家看见值得思考的对象、矛盾或形状；
- 只用必要的准备动作建立核心条件；
- 让玩家主动进入、制造或使用关键关系；
- 在关键操作后提供集中、可见的反馈；
- 高潮后尽快结束，不追加清理劳动；
- 关卡规模、对象数量和流程长度与回报相称。

包装不需要制造虚假难度。近乎直白的呈现可以成为合格 baseline；它不因还能继续生长而被贬低，也不因是树根就自动免除无意义走位、高潮后清理或对象失职等实际缺点。

## Baseline 与设计树

每轮任务围绕一个体验核心形成一棵设计树。Designer 从 task-local 设计语料中提取结构逻辑，独立完成 baseline；baseline 通过硬证据与独立玩家侧质量门后，冻结为根节点。冻结意味着此 exact version 不再被静默修改，后续设计只能复制它并形成子节点。失败尝试保留在尝试日志中，不成为树节点。

树只承认两种结构性生长关系：

- 前序构造：玩家不是直接得到体验核心的前置局面，而是需要主动构造它；
- 后继应用：体验核心产生的结果不是直接收束，而是被后续局面继续使用，并反过来约束此前的构造。

增加机制不是第三种并列生长方向。Designer 可以自然引入当前玩家前序允许的机制；教练也可以点名某个尚未使用的具体机制，但它必须改变上述前序选择或后继反约束。若删掉该机制后，核心相关的选择与约束仍原样成立，它只是附加子题；若机制碰撞本身取代了原体验核心成为主要回报，应另开体验核心和设计树。

作品身份也不是第三种生长方向，而是所有节点都必须满足的同一性守门。子节点无论增加前序还是后继，都要把玩家实际经历的局面、操作和可见变化，与冻结 baseline 的体验核心和身份条件比较；若同一个具有区分性的玩家关系已经不成立，作品身份丢失，该节点不能冻结。机械条件只提供必要证据，不能单独决定作品身份；这个判断独立于下述前序与后继标准。

### 前序构造的非拼接标准

好的前序不是一条把玩家送到 baseline 起点的强制动画，也不是完成后整体退休的独立子题。Reviewer 应从实际布局和解路线判断：一个尚未理解“本关最终要构造什么核心局面”的熟练玩家，能否只靠局部判断轻松走完前序。若可以，新增内容没有让玩家为体验核心作选择。

合格前序会出现若干局部看似可行的构造方式，而玩家一旦预见体验核心所需的具体形状、接触面、顺序、操作侧或对象职责，就能显著压缩这些选择。错误构造可以自然形成死路或在后段暴露为不可用，但“制造多少 deadend”只是 reviewer 检查选择是否真实的证据，不是 designer 的设计指标；不得为了过检而人为堆陷阱。

### 后继应用的非拼接标准

单独在直白 baseline 后追加一段流程通常很容易产生拼接。合格后继必须消费体验核心留下的具体状态，并把约束向前传回：有些能够完成眼前核心动作的状态，不能完成整关；玩家因此需要重新理解前序究竟要构造哪一种核心局面。

可以用删除测试检查这种关系：若拿掉后继，前序中的某个关键构造选择会明显变得更显然、若干原本需要区分的核心完成状态会重新等价，那么后继确实参与了同一个谜题。若后继只在核心结束后另起任务，不改变玩家对前序的推理，它就是子题。因而后继通常在已有合格前序的节点上更自然；直接从 baseline 生长也不是禁止，但需要 baseline 本身存在可被后继区分的多种核心进入或完成状态。

### 生长与停止

每个已接受节点冻结后，教练只给一个当前最优先的宏观方向：从当前节点继续生长，或回到某个冻结祖先探索另一条关系。Designer 一次只实现这一条建议，不同时填满预设分支。

教练判断的是“这棵树还有没有具体、非拼接、仍以同一核心为主角的生长方向”，不是机械要求前序和后继各出现一次。当所有有价值方向已经实现、无法说出具体非拼接方向，或继续增长只会让原核心降为材料时，设计树才算充分。最终交付是这组冻结节点及其亲缘关系；人类再通过试玩决定哪些节点进入游戏。

## 审美的非补偿性

审美判断先问是否存在明确、可感、同题可修的缺点，例如无意义赶路、未兑现对象、喧宾夺主的前置流程、高潮后的清理劳动、割裂子题、视觉不谐或作品身份弱化。

任何明确缺点都不能靠事件覆盖、逻辑完整、难度、对象数量或其它亮点补偿。同时，设计野心与完成质量应分开：保守选择可以形成无缺点的完整作品；激进尝试可能达到更高上限，也可能整体失败；“还可以另做一关更宏大的作品”不等于当前版本存在瑕疵。

LLM 不负责给存活版本作最终审美排名。人类试玩与作者判断拥有最终权威。

## 工具与结构材料

Solver、graph、replay、counterfactual 和 event probe 只验证硬事实：可解性、解族和旁路，操作与状态变化是否真实，核心对象是否参与，以及作品身份中的机械关系是否成立。

机械证据只有约束和否决作用，不提供正向审美价值。证据齐全不能成为停止设计或提交作品的理由，证据驱动的修订也可能削弱包装、作品身份和玩家体验。

工具不能证明关卡好玩、优雅、惊喜或应该进入游戏。Task-local explorer、Lexicon、Mechanism Lab、矿工和局部结构库也只提供材料；材料被 designer 提取、变形、选入明确体验核心并完成包装后，才成为作品的一部分。

## 结构修订：从差异到结构责任

结构修订以玩家关系为单位。出现 bypass、证据不支持设计声明，或生长方向在当前布局中没有空间成立时，先同时重放预期解与反例，找出它们实际分离的关系：对象尺寸或职责、进入方向、操作顺序与时机、必须保留的可达空间，或核心动作之后形成的局面。把修订目标说成“预期关系可以继续成立，而旁路所依赖的关系不能成立”，再决定怎样改变布局。

墙、地形、对象位置和目标位置是最小的局部约束手段。它们适合直接表达已经找出的差异；如果当前狭窄画布无法同时容纳预期操作和所需限制，可以插入行列、平移局部区域或增加必要的可动空间。修订时保存的是对象关系、操作方向和因果责任，不是原布局的绝对坐标。扩图和平移仍然可以属于同一结构 family，不应仅因原尺寸放不下就放弃当前设计。

随后从允许的设计语料、task-local Mechanism Lab、手画或工具探索中寻找能够利用该差异的结构。委派给 explorer 的问题应改写成局部设计空间，例如“三格黏块保留操作位、两格替代物失去操作位的筛选结构谱”。Designer 保留当前 exact 与 family 的设计责任，从返回材料中提取结构旋钮，自行改造局部摆法、组合消费端或围绕差异构造；现成材料不是穷尽清单。

筛选结构嵌入后，先确认预期解仍有足够操作空间，并实际重放预期解和已知反例。然后重新组织整张布局：移除为嵌入而产生的脚手架，收回冗余空间和无意义移动，调整局部位置以恢复可读性、节奏与回报，再检查扩图和重排是否生成新的旁路。扩充与紧缩可以在一次修订中往返多次；它们是服务同一结构责任的设计操作，不是必须逐项完成的流程表。

只要所需约束能够在不改变主要体验的前提下由当前 family 表达，就继续修订这个 family。只有可行表达都会让筛选器取代体验核心、破坏作品身份，或反例证明原结构假设本身不成立时，才更换 family。设计树的生长节点也使用同一方法：冻结父节点提供体验核心和玩家关系的比较基准，不要求在父节点地图上直接加建；designer 可以重新组织空间，让本轮前序构造或后继应用真正承担责任。

任何结构修订都会形成新的 exact version。旧 replay、证据和审查不能替代对新布局的重新读取与验证。

## 防漂移检查

每次实质修改后检查：

1. 玩家最终见证或完成的事情是否仍与体验核心相同；
2. 作品身份条件是否仍在规范解和所有允许胜解中成立；
3. 新增内容是否改变玩家与核心的关系，还是只增加流程；
4. 新增的、位于体验核心前序或后序的内容是否与核心形成玩家可感关系，而不是独立子题串联；
5. 修唯一解是否把整体形状降解成局部材料、把主动使用降解成被动动画。

## 例子

### 主动构造成功

Reality Anchor 的 `RA_CAND_0025` 用很短的前置让玩家主动形成 L 形，再反复将其作为活塞使用。前置构造没有抢走主要体验，终局目标布局继续提示并使用该形状。

### 包装吞没核心

`RA_CAND_0031` 用较大地图和长前置流程触发多种机制，最终只兑现较弱的重复拉动关系。前置对象和空间没有在主要体验中继续承担责任，形式完整不能补偿回报不足。

### 子题割裂

`RA_CAND_0032` 的前段双锚交接完成后整体退休，后段另起黏块目标题。两段各自必要仍不构成统一作品。

## 方法边界

本方法不要求 explorer 穷尽设计空间，也不能替代作者对机制和完整游戏节奏的理解。持续材料探索增加 designer 可调用的结构词汇；材料多少不评价设计方向，哪些作品最终进入游戏仍由人类试玩决定。
