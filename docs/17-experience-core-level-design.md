# 玩家体验核心与关卡包装方法论

状态：当前通用关卡设计方法论。

本文定义 Sokoban-like 关卡创作的设计本体，只回答“这关为什么值得存在、玩家实际体验什么、包装怎样服务它”。执行循环见 [关卡设计工作室执行标准](21-level-design-studio-standard.md)；规则、runtime 与工具事实以原型文档为准。

## 基本命题

关卡首先是一段由玩家亲自见证或完成的具体体验；地图、步骤、机制组合和唯一解约束都应服务这段体验。

关卡设计是一种以硬证据为前提的艺术创作，不是机械合格题的批量生产。可解、唯一、无旁路或机制必经，只说明版本满足硬证据，可以称为一个关卡，不说明它有趣、完整或值得存在。面对机械成立的版本，designer 仍应追问：在不改变当前体验核心、作品身份和设计野心的前提下，是否存在明确、玩家可感的改进方向；若存在，它仍是设计中的作品。

```text
玩家体验核心
-> 作品身份
-> 包装
-> 地图与操作
-> 硬证据验证
```

## 体验种子、最小 witness 与设计材料

人类输入可以只是一个值得研究的结构、现象或关系，例如“C 形黏块”，不需要预先写出完整体验核心或亲自提供最小 witness。这类输入称为体验种子。

Explorer 先把体验种子操作化为最小 witness：一个极小、可运行、能通过非空输入清楚复现现象的实验局面。预制 C 形结构移动到同形目标可以构成直白 witness；它证明玩家见证了这个结构的运动，却未必证明完整形状不可替代或存在更深用途。

最小 witness 是实验装置，不是最小关卡，更不是 baseline。若正式版本只是把 witness 封在几步显然或必然操作中，它仍未成为完整作品。

Explorer 再围绕 witness 生产任务内设计材料：具体开始局面、玩家动作、可见变化、由此改变的后续操作关系、近邻退化和证据引用。旋转、平移、换皮、重复次数和额外走位不会自动形成新材料；只有玩家关系发生实质变化时才应分开记录。

## 玩家体验核心

玩家体验核心描述玩家最终应亲眼看到或主动完成、并使本关值得存在的事情。它必须写成玩家可感的局面、操作与变化，不能只写机制名、事件标签或抽象主题。

至少应说清：

- 玩家此前相信或预期什么；
- 开局或关键阶段出现什么矛盾、形状或可能性；
- 玩家实际执行什么操作；
- 棋盘发生什么可见变化；
- 为什么这次变化值得独立成为一关。

体验核心可以是规则首次被完整见证、看似死局的结构被救活、整体形状获得意外用途、玩家主动制造并使用某种状态，或两条已知规则碰撞后产生新的解释。

它不要求“组装机器”。构造也可以是构造死角、操作面、材料状态、边界关系、顺序窗口、通路或时机。

## 默认玩家先验

除非当前原型明确把不完全信息或精确操作本身作为机制，否则默认玩家拥有全图视野、基本类推箱经验、当前关卡位置要求的全部前置知识，以及正常的人类几何直觉和操作能力。玩家能够迅速识别显然的操作方向、基本可达性、局部几何关系和短死路，也能够稳定完成走位、绕位与对准。

读图失误、规则遗忘、操作不准、执行唯一操作，不构成谜题内容。判断难度时，应把这些已被玩家先验剪除的负担视为已经解决；只有其后仍需玩家建立的非显然关系、计划或选择，才可能构成谜题难度。一个简单作品可以因核心清楚、包装准确而成立，不需要虚构玩家困难来证明它“有题”。

人类玩家与 LLM 及其工具具有不同的能力结构。人类玩家通常更擅长整体读取棋盘、使用几何直觉、迁移前置关卡形成的技巧，以及从有意安排的构图和对象位置或不谐元素中推断设计意图，这些方面 LLM 不是普通玩家的能力下界；LLM 与求解工具更擅长机械枚举、保存大量状态和发现偶然可行路线。关卡设计应主动以人类玩家擅长的能力作为主要参与方式，让玩家通过读取结构、迁移知识和理解作者安排获得进展；机械试错主要用于后台探索与验证，不能被直接当作玩家难度或作品价值。

## 作品身份

作品身份把体验核心转化为可证伪的创作承诺。它不评价作品好坏，而是规定哪些关系消失后，这已经不是同一关。

```yaml
experience_statement: 玩家具体见证或完成什么
player_action: 玩家必须亲自做什么
visible_payoff: 关键操作后哪里发生可见变化
core_boundary:
  central_objects: 体验核心本身包含哪些对象或机制
  supporting_objects: 哪些对象只承担包装或反馈
identity_conditions:
  - 必须保持的形状、关系、时序或对象责任
identity_counterfactuals:
  - 替换、删除或预先满足某个条件后，核心体验为什么不再成立
```

作品身份优先使用正面关系描述。例如“完整 C 形在关键操作前保持连通，凹口提供操作位，上下臂在同一次刚体移动中作用于两条物体线”，而不是罗列与作品无关的禁令。

## 包装

包装是为了呈现、准备、揭示、兑现和收束体验核心而存在的全部结构，包括开局构图、短测试、走位、前置准备、错误反馈、高潮与结束方式。

良好包装通常做到：

- 开局让玩家看见值得思考的对象、矛盾或形状；
- 只用必要的准备动作建立核心条件；
- 让玩家主动进入、制造或使用关键关系；
- 在关键操作后提供集中、可见的反馈；
- 高潮后尽快结束，不追加清理劳动；
- 关卡规模、对象数量和流程长度与回报相称。

包装不需要制造虚假难度。近乎直白的呈现也可以成为完整作品；只要它没有明确的同题改进方向，就不应因缺少第二个洞见、额外分支或更长流程而被贬低。

## Baseline 与后续设计方向

每个体验核心先制作 baseline。Baseline 是当前体验核心直接、完整、低风险的作品实现。它可以包含主动操作、状态构造或多个机制；判断依据是这些内容是否属于兑现作品身份的自然组成，而不是它事后能否被贴上其它标签。

Baseline 之后可以从三个方向继续设计：

### Application

相对于 baseline 增加玩家作者性：玩家主动建立体验核心成立的条件，或者在更完整的情境中使用核心。必须说明 baseline 直接提供了什么、玩家新增了什么责任，以及预先满足该责任后是否会退化回 baseline。

### Combination

引入另一个不同且非本核心前序的机制，使两种机制在同一主要体验中形成玩家可感的关系，例如共同改变构造、操作空间、时序、状态、路线或终局去向。

玩家为理解当前核心必然已经掌握的前序语义，不能仅为了分档被重新命名为“另一机制”。两个互不干涉的子题依次完成，也不构成有效组合。如果两种机制的碰撞本身成为最值得见证的事情，应建立新的体验核心。

### Challenge

在体验核心仍成立的前提下，探索难度、空间规划、构造自由度、多阶段复用、反直觉程度、玩家作者性或形式美感的上限。更多步骤、对象、事件和更长因果链不能单独证明挑战成立；读图、对准、规则回忆、显然操作和可被玩家先验立即剪除的短试错也不能充当挑战。

这些名称是画布局前用来打开不同创作方向的承诺，不是完成后给成品贴的分类标签。一个实际关卡可能同时具有主动构造和机制组合；designer 仍需选择本轮主要方向，独立 reviewer 检查实际作品是否足以承担该方向，但不要求它只属于一个类别。

## 连续作品观

围绕同一体验核心设计多个关卡时，应把它们视为可能被一个已有基本类推箱游戏经验、已完成前序机制所有关卡的玩家连续游玩的一段作品，而不是分别完成几个槽位。目标是：每一关独立完整，同时让玩家获得顺序合理、逐步深入、两两有显著差异且不可相互替代的多次体验，完成整段后，玩家应当已经体验到在当前体验核心最主要且值得单独成关的几种可能性。

后续关卡不能只是给前一关增加少量操作、扩大地图或替换几何外形。如果移除其中一关，整段应当损失一种可被玩家感知的体验，而不只是损失一个形式不同的谜题。

这是一项创作导向。Designer 在开始每个新关卡前，应重新查看当前批次已有作品的实际布局和解法，再明确本关准备增加的玩家体验及其与已有作品的具体差异。文字声明只用于调整创作方向；reviewer 可以根据整批实物否决具体同质或 slot 漂移，但“是否已经充分展示全部主要可能性”仍由人类试玩判断。

## 审美的非补偿性

审美判断先问是否存在明确、可感、同题可修的缺点，例如无意义赶路、未兑现对象、喧宾夺主的前置流程、高潮后的清理劳动、割裂子题、视觉不谐或作品身份弱化。

任何明确缺点都不能靠事件覆盖、逻辑完整、难度、对象数量或其它亮点补偿。同时，设计野心与完成质量应分开：保守选择可以形成无缺点的完整作品；激进尝试可能达到更高上限，也可能整体失败；“还可以另做一关更宏大的作品”不等于当前版本存在瑕疵。

LLM 不负责给存活版本作最终审美排名。人类试玩与作者判断拥有最终权威。

## 工具与结构材料

Solver、graph、replay、counterfactual 和 event probe 只验证硬事实：可解性、解族和旁路，操作与状态变化是否真实，核心对象是否参与，以及作品身份中的机械关系是否成立。

机械证据只有约束和否决作用，不提供正向审美价值。证据齐全不能成为停止设计或提交作品的理由，证据驱动的修订也可能削弱包装、作品身份和玩家体验。

工具不能证明关卡好玩、优雅、惊喜或应该进入游戏。Explorer、Lexicon、mechanism lab、矿工和局部结构库也只提供材料；材料被 designer 选入明确体验核心并完成包装后，才成为作品的一部分。

## 防漂移检查

每次实质修改后检查：

1. 玩家最终见证或完成的事情是否仍与体验核心相同；
2. 作品身份条件是否仍在规范解和所有允许胜解中成立；
3. 新增内容是否改变玩家与核心的关系，还是只增加流程；
4. combination 中另一机制是否与核心形成玩家可感关系，而不是独立子题串联；
5. 修唯一解是否把整体形状降解成局部材料、把主动使用降解成被动动画；
6. 相比现有作品，本关是否真的增加了玩家体验，而不是只增加步骤或形式差异；
7. 如果发现另一种有趣作品，是否已经另开体验核心或候选，而不是修改原承诺。

## 例子

### 主动构造成功

Reality Anchor 的 `RA_CAND_0025` 用很短的前置让玩家主动形成 L 形，再反复将其作为活塞使用。前置构造没有抢走主要体验，终局目标布局继续提示并使用该形状。

### 包装吞没核心

`RA_CAND_0031` 用较大地图和长前置流程触发多种机制，最终只兑现较弱的重复拉动关系。前置对象和空间没有在主要体验中继续承担责任，形式完整不能补偿回报不足。

### 子题割裂

`RA_CAND_0032` 的前段双锚交接完成后整体退休，后段另起黏块目标题。两段各自必要仍不构成统一作品。

## 方法边界

本方法不能保证 explorer 穷尽设计空间，也不能替代作者对机制和完整游戏节奏的理解。持续材料探索和连续作品观只能改善 designer 的创作方向；哪些作品最终进入游戏，仍由人类试玩决定。
